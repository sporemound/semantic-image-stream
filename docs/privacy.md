# Privacy and download safety

Whisper transcription, narrative interpretation and image ranking execute locally. Raw audio stays in bounded memory queues and is not written to disk by the application. The complete recognized transcript and narrative context are retained in memory for the current book session, including across Stop/Start. They are not stored in SQLite or restored after the app closes. Older transcript text discarded by an earlier version is unrecoverable.

Full-session interpretation sends new transcript passages, the established narrative summary and optional book background to the local Ollama service at `127.0.0.1:11434`. The endpoint is fixed to loopback, environment proxies are disabled and redirects are not followed. Before using a model, the app requires its complete cached GGUF weights and checks that the service reports the matching local model digest. Cloud model names and absent/incomplete weights are rejected; the app does not pull a narrative model automatically. The setup instructions describe a manual first download. If needed, the app starts the local service with cloud access disabled; it does not terminate that shared service when monitoring closes.

Each new passage must be processed successfully before the narrative cursor advances. The raw full-session transcript remains available to image/text embedding ranking; all retained text contributes through token-weighted windows, alongside the current scene and summary. The Context tab shows how many recorded segments have been processed and any backlog. Model failures leave the transcript available for retry while recognition continues.

Selected image providers receive sanitized queries of at most eight words, not raw audio, the complete transcript or narrative summaries. URLs, emails, long numeric identifiers, query operators and file paths are removed. Names and sensitive topic words can still appear in a query: sanitization is not guaranteed anonymization. Start monitoring only material you want represented in image searches. No paid API, subscription or credential is required. First-use Whisper and CLIP downloads contact Hugging Face; provider searches and image downloads reveal network/IP information to those hosts.

The default storage folder is `%LOCALAPPDATA%\SemanticImageStream` on Windows and the cache-home location on Linux. SQLite stores queries, URLs, licenses, image metadata and displayed-image history. History is capped at 500 rows and can be disabled with `history_enabled = false`. Query results expire after 24 hours. Image files are pruned toward a 512 MB limit; model files are separate, and recent prefetched/displayed image paths are temporarily protected, so total disk usage can exceed that image-cache limit. Models are not removed by **Clear cache**, to avoid downloading them again.

Stop monitoring to enable deletion controls. **New book / clear context** clears the in-memory transcript, interpreter state, optional book background and playback history while keeping image caches. **Delete session history** also removes SQLite displayed-image records and clears the local transcript/interpreter state; the configured background remains available. Changing **Book or context** starts a fresh session on the next Start and explains the reset in the status line. **Clear cache** deletes queries, image metadata, stored history and regular owned cache image files; model weights remain. Exported images and attribution JSON files remain where the user saved them. Deletion is ordinary filesystem/database deletion, not forensic secure erasure. Ollama model files are separate from the app's cache and follow the Ollama model location.

Downloads use HTTPS, no embedded credentials, and no environment proxies. Literal addresses, DNS answers and every redirect are checked against private/local/link-local destinations. The default httpx connection resolves DNS separately after validation, so a malicious host can still exploit DNS rebinding. This implementation does not claim complete SSRF protection; pinning the validated IP at the transport is a future hardening task. Source-page links open only HTTP/HTTPS in the user's browser.

Downloads have total and per-read deadlines, up to three redirects, a 15 MB byte bound and a 40-million-pixel decode bound. SVG and executable/non-image formats are rejected. PIL verifies the image, enforces actual resolution/aspect rules, checks known generated-image metadata, normalizes orientation, strips embedded metadata and re-encodes a safe static raster before caching. Perceptual hashes suppress near-duplicates. Updated image libraries remain necessary: these checks do not prove arbitrary image parsers cannot have vulnerabilities.

Console logs contain operational status, not raw audio or full transcripts. HTTP debug logging is disabled even with `--verbose`. The UI includes the privacy notice next to monitoring controls. There is no telemetry or analytics client.
