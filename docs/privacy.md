# Privacy and download safety

Whisper transcription, topic analysis and ranking execute locally. No raw audio is uploaded. Raw audio stays in bounded memory queues and is not written to disk by the application. The current transcript and semantic context stay in memory; they are not stored in the SQLite history database.

Selected providers receive sanitized queries of at most eight words, not the complete transcript. URLs, emails, long numeric identifiers, query operators and file paths are removed. Names and sensitive topic words can still appear in a query: sanitization is not guaranteed anonymization. Start monitoring only material you want represented in image searches. No paid API, subscription or credential is required. First-use model downloads contact Hugging Face; provider searches and image downloads reveal network/IP information to those hosts.

The default storage folder is `%LOCALAPPDATA%\SemanticImageStream` on Windows and the cache-home location on Linux. SQLite stores queries, URLs, licenses, image metadata and displayed-image history. History is capped at 500 rows and can be disabled with `history_enabled = false`. Query results expire after 24 hours. Image files are pruned toward a 512 MB limit; model files are separate, and recent prefetched/displayed image paths are temporarily protected, so total disk usage can exceed that image-cache limit. Models are not removed by **Clear cache**, to avoid downloading them again.

Stop monitoring to enable deletion controls. **Delete history** removes SQLite displayed-image records, transcript/topic panels and the current in-memory history. **Clear cache** deletes queries, image metadata, history and regular owned cache image files; model weights remain. Exported images and attribution JSON files remain where the user saved them. Deletion is ordinary filesystem/database deletion, not forensic secure erasure. To remove everything including models, close the app and remove the configured app data directory using Windows Explorer after checking the path.

Downloads use HTTPS, no embedded credentials, and no environment proxies. Literal addresses, DNS answers and every redirect are checked against private/local/link-local destinations. The default httpx connection resolves DNS separately after validation, so a malicious host can still exploit DNS rebinding. This implementation does not claim complete SSRF protection; pinning the validated IP at the transport is a future hardening task. Source-page links open only HTTP/HTTPS in the user's browser.

Downloads have total and per-read deadlines, up to three redirects, a 15 MB byte bound and a 40-million-pixel decode bound. SVG and executable/non-image formats are rejected. PIL verifies the image, enforces actual resolution/aspect rules, checks known generated-image metadata, normalizes orientation, strips embedded metadata and re-encodes a safe static raster before caching. Perceptual hashes suppress near-duplicates. Updated image libraries remain necessary: these checks do not prove arbitrary image parsers cannot have vulnerabilities.

Console logs contain operational status, not raw audio or full transcripts. HTTP debug logging is disabled even with `--verbose`. The UI includes the privacy notice next to monitoring controls. There is no telemetry or analytics client.
